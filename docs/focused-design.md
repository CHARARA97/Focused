# Focused 应用设计

> **状态：已实现**（`focused/`，196 项测试）。看板见 `focused/focused/ui.py`，
> 插件模型见 `focused/focused/plugins.py`，使用文档见 [focused.md](focused.md)。

> 目标：**一个能独立用的专注应用**，同时是一块**可被第三方小插件接入的平台**。
> 游戏插件（ChillFocused）和浏览器扩展只是它的两个前端；没有它们，Focused 自己也能完成
> "选黑名单 → 开始专注 → 挂起打扰你的应用 → 结束后原样恢复"这一整条。

---

## 1. 形态与边界

| 层 | 内容 | 依赖 |
|---|---|---|
| **核心引擎** | `focused/core/`：读 `/proc`、cgroup 规则、冻结器、规则判定、内置护栏、审计 | 只用标准库 |
| **应用** | `focused/`：配置、会话与 claim、事件流、插件注册表、HTTP API、UI | 只用标准库 |
| **界面** | 本地网页看板（`GET /`），无构建步骤、无外部资源 | 浏览器 |
| **前端/插件** | 游戏插件、浏览器扩展，以及别人写的小插件 | 走 HTTP 契约 |

**刻意的取舍**：不引入 GTK/Qt/Electron。
- 看板用服务端渲染的 HTML + 一点原生 JS：任何桌面、任何浏览器都能开，跨 Wayland/X11，
  不需要装运行时，也能在 SSH/无头环境下用 `curl` 完成同样的事。
- 想要原生托盘/菜单的插件可以自己做（走同一套 HTTP 契约），核心不替它决定。

**独立可用意味着**：装完就有完整功能，不需要游戏、不需要浏览器扩展。
`~/.config/focused/config.json` 里写一个黑名单，`focusedd --session 25` 就能用。

## 2. 界面信息架构

单页 + 左侧固定导航，六个区域。每个区域都"一眼看出当前状态 + 一个明确动作"。

```
┌ Focused ─────────────────────────────────────────────────────────────┐
│  ● 专注中 24:13   已冻结 3      [结束专注] [放行 10 分钟] [全部恢复] │  ← 顶栏常驻
├──────────────┬──────────────────────────────────────────────────────┤
│ 概览          │  会话面板：倒计时/番茄钟/正向计时 · 时长可填        │
│ 应用名单      │  已冻结列表：firefox（整单元 app-firefox-1.scope）    │
│ 网址名单      │  最近事件：16:48 冻结 firefox · 来源 chillfocused      │
│ 插件          │  本轮：开始 16:20 · 来源 Focused 自己 / 游戏计时       │
│ 设置          │  运行环境自检：cgroup v2 ✓ · 状态文件 ✓ · 审计 ✓      │
│ 日志          │                                                       │
├──────────────┴──────────────────────────────────────────────────────┤
│ 应用名单                                                             │
│  当前运行中（搜索框）  [x] firefox ×3   [ ] code ×2   [ ] qq ×1      │
│  已选名单： firefox ✕   qq ✕         [+ 手动输入名字] [通配符说明]     │
│  保护名单（只增）： wineserver …（内置 446 条，不可移除）[+ 添加]      │
│  按启动参数匹配： --profile=distraction ✕  [+ 添加]                  │
├──────────────────────────────────────────────────────────────────────┤
│ 插件                                                                 │
│  ● chillfocused  v0.1.0  已连接 12s 前   规则 2 条 · 会话租约 30s [禁用]│
│  ● focused-extension    已连接 3s 前   网址名单 4 条           [禁用]│
│  ○ （未注册）                      新插件接入说明 + 一键复制令牌      │
└──────────────────────────────────────────────────────────────────────┘
```

要点：

- **顶栏永远回答"现在发生了什么、我能按什么"**：状态 + 倒计时 + 三个动作。
- **概览**把"我为什么被冻着"讲清楚：谁开的会话（自己 / 游戏计时 / 别的插件）、冻了谁、最近事件。
  会话面板支持三种模式（倒计时 / 番茄钟 / 正向计时），时长在页面上直接填、可保存为默认值；
  番茄钟的休息阶段 `active` 为 false，应用自动回到你手里。
- **应用名单**是核心工作区：从"当前运行中"勾选即可（带搜索、带"受保护"标记与原因），
  也可以手输通配符；保护名单只增不减（内置护栏灰显、不可移除）。
- **网址名单**给浏览器插件用：明确写着"本名单由浏览器插件读取，Focused 不会自己关标签页"。
- **插件**页列出每个已注册插件：名字、版本、最后心跳、贡献了几条规则、有没有会话租约、
  有没有刷错误；可禁用/移除，并可复制新插件的注册说明与令牌。
- **设置**：端口/令牌、`dry_run`、默认会话时长、放行时长、扫描间隔、插件目录、审计文件路径；
  保存即写入 `config.json`（原子替换）。
- **日志**：审计尾部 + 事件流（可过滤），只读。

**实时性**：看板 2 秒轮询 `/api/v1/status` + `/api/v1/events?since=`；操作按钮 POST 后立刻刷新。
没有 WebSocket（多一个协议、多一类失败模式，收益只是把 2 秒变成 0.1 秒）。

**可用性硬要求**：所有危险动作都有撤销路径——「结束专注」「全部恢复」永远可见；
`dry_run` 打开时顶栏常驻黄色提示；不配令牌时看板显示"仅本机可用"。

## 3. 插件模型（两级）

### 3.1 HTTP 插件（推荐，任何语言）

一个插件 = 一个稳定 id + 一个令牌 + 三条能力：

| 能力 | 端点 | 说明 |
|---|---|---|
| 贡献规则 | `PUT /api/v1/plugins/{id}/rules` | 黑名单（名字/命令行/PID）、网址名单、保护名单（只增） |
| 认领会话 | `POST /api/v1/plugins/{id}/session` | `{"active":true,"ttl_seconds":30}` 租约；`active:false` 主动放弃 |
| 读状态/事件 | `GET /api/v1/focus` · `GET /api/v1/events?since=` | 会话状态、冻结列表、事件流 |
| 注册 | `POST /api/v1/plugins/register` | `{name, version, kind, webhook_url?}` → 返回 `id` 与 `token` |

**多来源合并规则**（关键设计）：

- 黑名单：**并集**（每个来源各贡献一份，互不覆盖）。谁想撤掉自己的规则，
  给自己的那份推空数组即可——不会影响别人。
- 保护名单：**并集，且只增不减**。任何来源都不能削弱护栏。
- 会话：**claim 模型**。`active = 自己起的会话 ∨ 任一来源持有未过期租约`。
  任一 claim 活着就冻结；全部过期 → 自动当会话结束 → 全部解冻。
- 网址名单：并集，供浏览器插件读取。

**为什么用租约而不是布尔值**：前端是插件，插件会崩、会被杀、会被系统冻住。
租约把"我还在专注"变成一个必须持续证明的声明，没人续期就自动收手（见 `freeze-mode.md` F1–F5）。

### 3.2 进程内 Python 插件（可选，深度扩展）

放在 `~/.config/focused/plugins/*.py`，模块里提供：

```python
def register(focused):
    """返回元信息；focused 提供引擎句柄（见 docs/focused.md）。"""
    return {"name": "pomodoro", "version": "0.1.0"}

def on_event(focused, event):     # 事件回调，短小、不要阻塞
    ...
```

用途：需要**引擎内视野**的扩展——例如"从别处（日历/番茄钟/公司打卡）决定什么时候算专注"、
"记录统计"、"冻结时顺带静音"。

**隔离与安全**：插件在自己的模块里跑（与 Focused 同进程），所以：
- 加载失败 / 抛异常 → 记一条事件并**禁用该插件**，绝不拖垮应用主循环；
- 插件只能通过传入的句柄操作（有明确 API），不用 import 内部模块；
- 插件清单与状态存 `plugins.json`，UI 里可一键禁用；
- 文档里明确写：进程内插件 = 完全信任（它跟 Focused 同权限），不信任的请写 HTTP 插件。

## 4. API 一览（新增部分）

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/` | 看板 |
| GET | `/api/v1/status` | 完整状态（含插件、claim、来源、统计） |
| GET | `/api/v1/focus` | 前端读的扁平会话状态（**保持向后兼容**） |
| GET | `/api/v1/focus/frozen` | 当前冻结列表 |
| PUT | `/api/v1/focus/rules` | 旧式全局规则（自带前端用；等价于一个内置来源 `builtin`） |
| POST | `/api/v1/focus/state` | 旧式会话状态（等价于来源 `client` 的 claim） |
| POST | `/api/v1/focus/session` · `/pause` · `/thaw` · `/scan` | 应用自身动作 |
| GET/PATCH | `/api/v1/config` | 读写配置（PATCH 只改给出的段，原子保存） |
| GET | `/api/v1/processes` | 运行中进程（并行基础数组 + 对象数组） |
| GET | `/api/v1/events?since=N` | 事件流（冻结/解冻/会话/插件/错误） |
| POST | `/api/v1/plugins/register` | 注册插件 → id + token |
| GET/DELETE | `/api/v1/plugins` · `/api/v1/plugins/{id}` | 列出/移除插件 |
| POST | `/api/v1/plugins/{id}/enable` | 启用/禁用 |
| PUT | `/api/v1/plugins/{id}/rules` · `POST …/session` | 插件贡献规则 / 认领会话 |
| POST | `/api/v1/plugins/{id}/webhook` | 设置/清除事件回调地址 |

**鉴权**：`X-Focused-Token`。全局令牌为空时只允许回环（本就只绑回环）。
每个插件有自己的令牌；`id` + 令牌不匹配 → 401。自带前端可以用全局令牌（等价 `builtin` 来源）。

**事件**：`{seq, ts, kind, source, name, pid, detail}`，环形缓冲（默认 200 条）；
`kind ∈ {session-started, session-ended, lease-expired, frozen, thawed, rules, plugin, error, paused}`。
有 `webhook_url` 的插件会收到 `POST`（best-effort，失败只记事件，不重试风暴）。

## 5. 独立使用路径（三个入口，同一引擎）

1. **看板**：`http://127.0.0.1:8766/` —— 选名单、开始专注、看冻结、放行、恢复。
2. **CLI**：`focusedd --session 25` / `--status` / `--frozen` / `--thaw-all` /
   `--add-name firefox` / `--add-url reddit.com`（脚本与快捷键友好）。
3. **HTTP**：任何语言的小插件或 `curl`。

## 6. 与现有前端的兼容

- `GET /api/v1/focus` 的字段**只增不改**：游戏插件和浏览器扩展已有的解析继续有效。
- `PUT /api/v1/focus/rules`、`POST /api/v1/focus/state` 保留为"内置来源"，行为等价于
  注册一个 id 为 `builtin` 的插件，因此迁移是渐进的：前端可以先照旧，之后再改成
  命名空间端点以获得多插件共存。
- `POST /api/v1/focus/state` 从 B2 起支持 `ttl_seconds` 租约；不带 TTL 的旧调用仍然有效
  （等价于无限期，直到显式 `active:false`）。

## 7. 测试策略

| 层 | 覆盖 |
|---|---|
| 规则合并 | 多来源并集、各自撤下互不影响、保护只增 |
| 会话 claim | 多个 claim、任一活着即冻结、全部过期即解冻、显式放弃 |
| 插件注册表 | 注册/令牌校验/禁用/移除/持久化；未知 id 401 |
| 配置 API | PATCH 局部更新、类型校验、原子写盘、重启后生效 |
| 进程列表 | 并行数组与对象数组一致（插件用数组，UI 用对象） |
| 事件流 | seq 单调、环形上限、webhook 失败不影响主流程 |
| 进程内插件 | 正常加载、抛异常被隔离并禁用、`register` 缺省被拒 |
| UI | 页面包含各区域 id、引用的端点存在、按钮对应端点真实可用（HTTP 冒烟） |
| 引擎 | 既有 174 项（真进程冻结/解冻、PID 复用、遗留恢复、租约） |

## 8. 非目标

- 不做云同步/账号；不做多用户（只看当前用户自己的进程）。
- 不做系统级托盘/原生窗口（交给愿意做的插件，接口已备好）。
- 不做"关掉进程"（终止路径已删除，只冻结；见 `freeze-mode.md` §12d）。
- 不做域名级拦截本身：Focused 只发布名单，真正关标签页的是浏览器插件。
