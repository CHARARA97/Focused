## 二、问题诊断

每条都指向上面清单里的具体内容。

1. **两套「开关」概念互相纠缠（最严重）**
   第 1、2 行分别是「专注状态」和「专注开关」，而面板里又有一个 `[开启]/[关闭]`。
   用户必须先理解「专注开关 ≠ 是否在拦截」才能读懂状态。实际上拦截由
   **计时器 + 开关 + `allow_manual_override`** 三者共同决定，却要用自然语言解释。

2. **同一个数据出现两次**
   已选黑名单在分区 2 顶部列一遍，运行中列表里又用 `✔` + `[移除]` 标一遍。
   用户看到 `firefox` 出现两次会怀疑是不是加了两条。

3. **术语是给维护者看的，不是给用户看的**
   `守护进程`、`规则`、`命令行子串`、`演练模式`、`手动强制`、`门控`
   —— 想「别让我分心」的用户一个都不需要知道。

4. **5 行技术状态与 1 行核心结论同等权重**
   HUD 里「现在到底有没有在拦」和「守护进程版本号」视觉上一样重。
   扫一眼分不出主次。

5. **原始错误直接甩给用户**
   `game-state push: another request is already in flight` —— 这是我该修的 bug，
   不该出现在玩家界面上。正确做法是显示「后台执行器未连接」并给一个重试入口。

6. **没有上手路径**
   黑名单为空时显示 `（空）`，不告诉用户下一步该做什么。
   新用户打开面板后第一反应是「然后呢？」

7. **HUD 默认常显且占 10 行**
   默认 `ShowHud = true`，直接盖在游戏画面上，而玩家 99% 的时间只关心一件事。

8. **`F8 强制扫描` 对用户无意义**
   扫描是每 1 秒自动发生的，手动触发只在我调试时有用。

9. **高级功能与常用功能同级**
   `命令行子串`、`字体来源`、`演练模式` 和「选要屏蔽的应用」摆在一起。

10. **没有任何操作反馈**
    点 `[加入]` 之后界面变化很小（只有 `✔` 变化），用户不确定是否生效。
    （已有 toast 机制，但没用在这里。）

## 三、设计原则

1. **一句话回答「现在在拦吗」** —— 其余信息都可以收起来。
2. **默认零配置可用** —— 装好之后开始番茄钟就应该自动生效，不需要先做选择题。
3. **一个概念一个控件** —— 不再出现「开关」和「状态」两套说法。
4. **渐进披露** —— 常用功能一眼可见，高级功能折叠，但**可手动展开**。
5. **技术术语集中到高级区**，且用大白话重写。
6. **每个操作都有反馈**（toast）。
7. **出错时说人话**，原始信息只在高级区可见。

## 四、新 HUD 设计

三种模式，配置项 `HudMode = Minimal | Detailed | Off`，默认 **Minimal**。

### Minimal（默认，1 行）

```
● 生效中 · 创作模式                       已冻结 3 个
```

未生效时：

```
○ 未生效 · 开始游戏计时后自动生效
```

- `●` 实心圆 = 正在冻结（用警告色）；`○` 空心圆 = 未拦截（灰）
  —— 圆点在 CJK 字体里一定存在，不用 emoji。
- 左侧是**唯一结论**，右侧是次要计数（可关）。
- 未连接时：`○ 未生效 · 后台执行器未连接`

### Detailed（展开，高级开关）

保留现有多行，但按语义分组、加空行：

```
● 生效中 · 创作模式

  原因    游戏计时器 1:23:45
  已冻结  firefox ×3 · qq · vivaldi-bin
  规则    3 个应用名
  执行器  已连接 v0.1.0
  热键    F10 暂停 · F7 设置
```

技术行（字体、演练模式、错误详情）**不再出现在 HUD**，只进设置面板的高级区。

### Off

完全不绘制。

## 六、交互逻辑

### 6.1 状态模型（把三个概念压成一个）

守护进程侧引入一个显式的 `mode`：

| mode | 含义 | 等价于现有配置 |
|---|---|---|
| `auto` | 只在游戏计时器运行时拦截 | `enabled=true` + `game_gate.enabled=true` + `allow_manual_override=false` |
| `always` | 始终生效 | `enabled=true` + `game_gate.enabled=false` |
| `off` | 不冻结 | `enabled=false`（且 `game_gate` 不生效） |

- 旧字段继续接受（向后兼容），加载时推导出 `mode`。
- `enforcing` 由 `mode` + 计时器状态算出，语义唯一，不再有三种解释。

**热键重定义**：

| 键 | 现在 | 改为 |
|---|---|---|
| F10 | 切换「专注开关」（含义暧昧） | **暂停 / 恢复**：`off` ⇄ `auto` |
| F9 | 切换 HUD | 不变（在三种 HUD 模式间循环） |
| F7 | 设置 | 不变 |
| F8 | 强制扫描 | **移除**（挪进高级选项的按钮） |

`F10 = 暂停/恢复` 是一句话能讲清的，而且恰好是用户最可能需要的一键操作。

### 6.2 面板打开时的行为

- 打开设置面板时**自动隐藏 HUD**（避免两块面板叠在一起），关闭后恢复原状。
- 面板打开时**不暂停拦截**（避免「打开面板就成了绕过手段」）。

### 6.3 反馈

| 操作 | 反馈 |
|---|---|
| 加入/移除应用 | toast `已加入 firefox` / `已移除 firefox`，列表立即更新（不等下拉刷新） |
| 切换拦截时机 | toast `拦截时机：跟随游戏计时器` |
| 刷新成功/失败 | 行内 `已获取 58 个` / `未连接，正在重试…` |
| 后台执行器断开 | 顶部结论行变 `未生效 · 后台执行器未连接`，不弹错误文本 |

## 九、实施记录

> 本节在实施后补写，记录与上面设计的差异。

**最重要的差异：手动专注模式被完全移除了。**

原设计提出三选一的「拦截时机（跟随计时器 / 始终生效 / 关闭）」。实施时确认的需求是
「不需要手动开启专注模式，直接全部按照是否开启番茄钟来判断」——于是：

- 插件的 `Enabled` 配置项、F10 专注热键、F8 强制扫描全部删除。
- 守护进程的 `allow_manual_override` **被整个删除**（不是改成默认 false）。
  原因见下：它与「插件总是武装主开关」叠加后，会让门控被静默绕过。
- 唯一剩下的行为开关是高级区里的「不依赖游戏计时器（始终生效）」，它对应守护进程的
  `game_gate.enabled = false`，服务于「不开游戏也要拦」这个场景。
- 热键只剩 `F9`（循环状态面板）与 `F7`（设置）。

其余部分按设计实施：HUD 三模式（默认极简一行）、合并重复列表、空状态引导、操作 toast、
高级选项折叠、术语全量替换、原始错误只在诊断区出现。

**为支持新界面新增的守护进程接口**

| 接口 | 用途 |
|---|---|
| `POST /api/v1/game-gate` | 高级区那个行为开关 |
| `/status` 的 `recent` | 详细面板的「最近冻结」 |
| `/status` 的 `closed_total` | 极简行的「已冻结 N」 |

`POST /api/v1/rules` **不接受** `game_gate` 字段（早期文档里的示例是错的，已改为上面的专用接口）。

**实施后修复的一个严重缺陷：门控被静默绕过**

两次改动叠加产生了这个 bug：

1. 为了让「不依赖游戏计时器」这个逃生口能用，插件改成**每个周期都推 `enabled = true`**（把主开关永久武装）；
2. 配置里 `allow_manual_override` 仍然是早期写入的 `true`。

而当时的判定公式最后一行是：

```python
return manual and self._gate.allow_manual_override
```

于是 `True and True` → **强制拦截**，与 `gate.satisfied` 无关。表现就是「番茄钟没启动也查杀进程」。

**修法不是改配置值，而是删掉这个概念**：判定收敛为两个分支，任何组合都无法绕过门控。

```python
if not self._gate.enabled:
    return manual                      # 逃生口：不依赖计时器，始终生效
return self._gate.state().satisfied     # 门控开启时，只有计时器说了算
```

并加了回归测试 `test_the_master_switch_cannot_bypass_a_stopped_timer`，
逐一验证「主开关武装 + 门控开启 + 计时器停止」的各种组合都不会执行。

**面板内部的重新组织（不改界面）**

界面按本文件重排完成后，`FocusRunner` 长到 1244 行、`SettingsPanel` 到 979 行，于是又做了一轮
